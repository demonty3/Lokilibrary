## 2 · The new question

The killed question was: should the engine's vertical-snapping invariant be
opened, with a window underneath as a second land? Killed on priority, stays
killed in that form.

The new question is: **can a window snapped underneath read as the SAME
wing's underground continuation** — no sky, all deep rock: caverns, ore,
relics, the descent shaft continuing down — so the pair reads as one place,
one wing, seen through two stacked apertures, with the shaft stitching them?

Doctrinal support this shape already has: IDEAS.md's side-on commitment
assigns the vertical axis exactly this meaning ("a **vertical stack** =
surface→underground strata"), and the shared-rules doctrine requires
conformance of shared truths at a join — which the underground read satisfies
by construction, since both windows show the same wing.

Engine facts established 2026-08-17 (exploration, recorded here for costing):
the shaft column is a pure function of the wing seed + width
(`land.ts:604`), so both windows can agree on it with no broker; the strata
band depths are `underH`-relative and derivable the same way; beings have no
vertical coordinate today, so descent is new machinery. Product decisions
already made (Harry, 2026-08-17): underground continuation, downward only,
mockup before any engine work. Display fact: two stacked 520px windows
(1040px) exceed the MacBook's ~830–875px work area, so the probe mocks a
**640×260** lower window — the size that would actually ship.

## 3 · Kill conditions — frozen 2026-08-17, before the mockup was first viewed

> **K1 (inherited, one-place):** if the stacked pair reads as two broken
> lands, not one place, the join fails and vertical stacking stays dead at
> this scope.

> **K2 (deep-rock legibility):** if the lower window does not read as THE
> SAME wing's deep rock — if at wallpaper distance it reads as a separate
> land, a second desk, or an unrelated texture panel rather than "the ground
> of the window above, continued down" — it fails.

> **K3 (seam):** if the seam demands a visible artefact that reads as window
> chrome rather than strata — if the eye parses a boundary bar between two
> programs instead of rock continuing through a gap — the continuation
> illusion fails.

Pass is a portal-free read: one wing through two stacked apertures, the shaft
stitching them, the 260px window reading as a place worth keeping open. These
bars do not soften after viewing; if the mockup misleads (authoring
artefacts, wrong registration, palette drift), fix the mockup and look again
— never reword the bar.

## 4 · Preconditions for any engine work

1. **The §3 eyeball passes** on this mockup (or a re-mock inheriting §3
   verbatim).
2. **The 640×260 under-window size is accepted** — judged by the same
   eyeball. If 260 reads too shallow to be a place, one re-mock at 640×320 is
   the pre-authorised iteration dial; still too shallow → the display
   constraint kills the feature on this hardware, and that is recorded as a
   clean negative.

Explicitly deferred, not judged here: the L-shape (a 2×1 horizontal desk with
one window below) — it multiplies seam questions (which upper window does the
lower one continue?); v0 is a vertical pair. The variable-size hall/storeys
idea (IDEAS.md §3) stays parked on its own precondition, untouched.
